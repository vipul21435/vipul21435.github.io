Adversarial evaluation tasks

Hard, verifiable tasks for coding-agent evaluation. Each ships self-contained: a digest-pinned Dockerfile that builds the environment for both the agent and the verifier, a reference solution that solves the problem by genuine computation, and a pytest suite that grades the agent's real output instead of matching strings.

A task is only hard if the naive reading of the data looks correct and is wrong, and the deciding cases are hidden from the sample but fully determined by it. It still has to be gradeable byte-exact. Getting there has meant generating synthetic corpora, proving computationally that each admits exactly one consistent interpretation, and recovering hidden structure with integer linear algebra and modular arithmetic.

Repositories rebuilt at a historical commit

Reproducible environments for arbitrary open-source repositories at a specific commit. I pin dependencies until a suite that failed before a fix passes after it, then verify that flip against the reference solution.

Submission pipeline tooling

Per-repository build recipes, collision detection against a shared ledger, build locks, dedupe caches, and the scripts that stop a multi-folder submission pipeline from burning the same work twice. Every task goes in as a pull request and iterates against automated review gates until each check is green.

research-harvest

Python

Searches PubMed and OpenAlex, merges the results, drops papers that appear in both, and reads what each abstract reports: the methods used, the cohort size and the best score claimed. The extraction is the hard part. An abstract is written for a human, so anything clever enough to catch every phrasing also catches a p-value and calls it a cohort.

research-harvest, before and after

  • Two scripts driving headless Chrome over PubMed and Google Scholar
  • A five second sleep between every article
  • 35 MB of chromedriver.exe committed, twice
  • Scholar output empty, because Scholar blocks automated access
  • PubMed and OpenAlex over their official REST APIs
  • Dedupe on DOI, then source id, then normalised title, keeping the fuller record
  • 115 tests, 95% coverage, run offline against recorded PubMed XML and OpenAlex JSON

CourseBot360

JavaScript, GitHub Pages

Answers questions about university courses. Try "info about DSA", "is there a lab in OS?" or "list CSE courses with quizzes under 10%". The intent engine never touches the DOM, so a whole conversation runs in a test in milliseconds. Answers come back as data, which keeps string concatenation out of innerHTML entirely.

CourseBot360, before and after

  • An extracted zip committed whole, nested folder and all
  • ReferenceError: speak is not defined on every single reply
  • Intent engine separated from the page, answers returned as { text, blocks }
  • 108 tests, deployed by GitHub Actions

There is no language model in it, on purpose. A static site cannot hold an API key without handing it to every visitor. For 31 fixed courses a parser over a local JSON file is faster, costs nothing, works offline and cannot invent a prerequisite.
