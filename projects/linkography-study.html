Linkography study of collaborative design

A study of how design methods shape ideation and cost in collaborative architectural design, done as a Research Intern at Ariel University, Israel, with the Human-Centred Design Lab, IIIT Delhi. Recorded design sessions became linkographs, the linkographs became numbers, and the numbers became a co-authored, peer-reviewed publication.

The question

Do design methods change how a team ideates, and what it costs?

Collaborative architectural design is a stream of moves: a proposal, an objection, a refinement, a return to an earlier idea. The question was whether the design method a team follows changes the shape of that stream, how ideas connect and build on each other, and what the session costs.

The material was a set of recorded design sessions for climate-acclimatised buildings. I framed the question with my advisor, designed the protocol, built the tooling, ran the analysis and wrote up the findings.

Method

From a recording to a linkograph to a number

A linkograph (Kan & Gero, 2008) maps every design move to the moves it draws on. Read forwards, a move's links show what it led to; read backwards, they show what it came from. The pattern of links is what gets measured.

  1. Record the sessions

    Collaborative design sessions for climate-acclimatised buildings were recorded as the material for the study.

  2. Transcribe move by move

    Each session was transcribed into a sequence of design moves, the unit a linkograph is built from.

  3. Code the links

    Every move was linked to the earlier moves it draws on. The coding scheme went through two full passes.

  4. Build the linkographs

    The coded moves and links became one linkograph per session, a graph of design moves.

  5. Compute the measures

    The Java modules computed the link index, the critical moves and the entropy of each session.

  6. Run the evaluations

    More than 150 structured evaluations went through the tooling.

  7. Write it up

    The findings became a co-authored, peer-reviewed publication.

The Java tooling

Why the analysis had to be code

Hand-coding at that density is not reproducible. Two people reading the same transcript will draw slightly different links, and the same person will draw different links on a different day. So I wrote the evaluation modules in Java that do the mechanical part the same way every time.

Encode moves

Each design move from the transcript is encoded as a node in the session's linkograph.

Record forelinks and backlinks

For every move the modules record the links forward to the moves that build on it and backward to the moves it draws on.

Link index and critical moves

From the links the modules compute the link index of the session and pick out its critical moves, the ones with the most connections.

Entropy per session

An information-theoretic entropy is computed for each session, so sessions can be compared on a number rather than an impression.

What was measured

The mathematics underneath

A linkograph is a graph of design moves. Three measures came out of each one: the link index, which relates how many links a session has to how many moves; the critical moves, the nodes with the most links; and an information-theoretic entropy over the session's link pattern.

Those three, computed the same way for every session by the Java modules, are the evidence the study compared design methods on.
